# AGENTS.md — English Quest: команда агентів

## Ролі

### 🧭 Координатор
- Тримає та оновлює `PLAN.md` (черга задач) і цей файл.
- Єдина роль, що напряму обговорює важливі рішення з Антоном (у чаті).
- Розбиває будь-яку задачу на task-картки (формат нижче) і призначає її потрібному агенту.
- Приймає результат: перевіряє DoD, мерджить або повертає на доопрацювання.
- На практиці: окрема Claude-сесія (не Claude Code), що не пише код сама, лише планує й ревʼює.

### 💻 Агент кодування
- Виконує одну task-картку за сесію → один PR у main (як вже заведено).
- DoD = сирий вивід команди (build/lint/test), не текстове твердження "готово".
- Джерело правди про стан проєкту — файли в репо (`CLAUDE.md` Current State, `PLAN.md`), не історія чату.

### ✍️ Контент-агент
- Генерує ДВА типи контенту:
  - **Навчальний**: нові уроки/вправи (23–24 і далі), тримає єдиний стиль/структуру секцій (SECTION 0–4).
  - **Маркетинговий**: тексти для постів і листів (сировина для маркетинг-агента).
- Працює з окремим `BRAND.md` (тон голосу, цільова аудиторія — батьки дітей 6–9, заборонені фрази тощо) — **ще не створено, перший крок цього агента**.
- Здає результат координатору як текст/файл, не публікує нічого сам.

### 📣 Маркетинг-агент
- Бере контент від контент-агента → готує чернетку посту/листа під конкретний канал.
- **Показує чернетку в чаті Антону → чекає схвалення → тільки після цього публікує.**
- ⚠️ Технічне обмеження зараз: реальна публікація в соцмережі потребує окремих інтеграцій (наразі підключені лише Gmail/Drive/Canva/Netlify/Supabase — жодної соцмережі). Email через Brevo — вже готовий (той самий ключ, що для send-email). Соцмережі — потрібно буде підключити конектор (Buffer/native API) окремим завданням, перш ніж агент зможе публікувати сам, а не лише готувати.

## Протокол передачі задачі (task card)

```
## TASK-<id>: <коротка назва>
Агент: <кодування|контент|маркетинг>
Контекст: <1-2 речення, чому це потрібно>
Скоуп: <що саме зробити, межі — що НЕ чіпати>
DoD: <перевірювана умова — команда/чекліст/приклад виводу>
Статус: todo|in-progress|review|done
```

Картки живуть у `PLAN.md`. Агент бере одну картку, робить, лишає результат (PR / файл / чернетку) — координатор рев'ює і закриває.

## Порядок запуску (як домовились)

1. Координатор + цей файл + `PLAN.md` — зараз.
2. Далі — розподіл перших задач: код (Vercel push + деплой), контент (BRAND.md + перші маркетингові тексти).
3. Маркетинг-агент активується, коли є що публікувати і вирішено питання соцмережевої інтеграції.
